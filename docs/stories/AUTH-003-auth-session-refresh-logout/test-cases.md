# Test cases: Silent session refresh, rotation, and logout

| ID | Title | Type | Linked scenario | Preconditions | Steps | Test data | Expected result | Priority |
|----|-------|------|-----------------|---------------|-------|-----------|-----------------|----------|
| TC-01 | Valid refresh rotates the token pair | Happy path | valid refresh rotates the token pair | Valid session | 1. `POST /refresh`<br>2. Inspect new vs old `jti`s<br>3. Retry the old access token before it expires | Valid refresh cookie | New pair issued; old refresh `jti` blacklisted immediately; old access token still valid until its own expiry | P1 |
| TC-02 | Replaying a rotated refresh token kills all sessions | Negative | replaying a rotated refresh token kills every session | Already rotated once | 1. Re-present the old (now-blacklisted) refresh token to `/refresh` | Blacklisted refresh token | 401; epoch set to now; all sessions (including the freshly rotated one) invalidated; WARN log emitted | P1 |
| TC-03 | Gateway check order is deterministic under multiple simultaneous failures | Edge | the gateway check order is signature, then expiry, then blacklist, then epoch | Token crafted to fail expiry AND blacklist simultaneously | 1. Present the token to any authenticated endpoint<br>2. Inspect the logged failure reason | Expired + blacklisted token | Logged reason matches the first failing check in order; response is 401 `AUTH_INVALID_TOKEN` either way | P2 |
| TC-04 | Downstream service does not call Redis | Regression | downstream services trust the gateway without their own Redis check | Redis instrumented to detect calls | 1. Make an authenticated request through the gateway to any downstream service<br>2. Monitor Redis calls from that service | — | Zero Redis calls originate from the downstream service; only signature/expiry checked there | P1 |
| TC-05 | Logout ends only the calling device's session | Happy path | logout ends only the current session | Logged in on 2 devices | 1. `POST /logout` from device A<br>2. Attempt a request from device A<br>3. Attempt a request from device B | 2 active sessions | Device A's tokens blacklisted and cookies cleared, session removed; device B unaffected | P1 |
| TC-06 | Logout-all invalidates every device in one O(1) write | Happy path | logout-all ends every session without enumerating tokens | Logged in on 3 devices | 1. `POST /logout-all` from one device<br>2. Attempt requests from all three | 3 active sessions | Epoch set once; all three devices fail their next request; no per-device blacklist writes observed | P1 |
| TC-07 | Idle refresh token beyond 14 days is rejected within the 30-day window | Negative | an idle session beyond 14 days cannot refresh even within the 30-day window | Refresh token issued 20 days ago, unused for 15 days | 1. `POST /refresh` | Idle refresh token | 401 `AUTH_SESSION_EXPIRED`; re-login required | P2 |
| TC-08 | Session refreshed regularly survives past 14 days | Edge | an active session survives past 14 days as long as it keeps refreshing | Token issued 20 days ago, refreshed every 3-4 days since | 1. `POST /refresh` | Actively-refreshed session | Refresh succeeds; absolute 30-day lifetime is the only remaining limit | P2 |
| TC-09 | Redis outage fails closed on refresh | Negative | Redis unreachable fails closed on refresh and open on reads | Redis stopped or unreachable | 1. `POST /refresh` while Redis is down | — | Request fails rather than succeeding unchecked; failure logged loudly | P1 |
| TC-10 | Redis outage fails open on a read with a structurally valid token | Edge | Redis unreachable fails closed on refresh and open on reads | Redis stopped or unreachable | 1. `GET` an own-data endpoint with a signature/expiry-valid token while Redis is down | Structurally valid access token | Request succeeds (blacklist/epoch check skipped, logged); read availability preserved | P2 |
| TC-11 | Every blacklist key carries a TTL | Regression | (NFR-03, story.md dependencies) | Token blacklisted via logout or rotation | 1. Inspect the `blacklist:{jti}` key in Redis immediately after creation | — | TTL present and equal to the token's remaining life; no key without a TTL | P2 |
