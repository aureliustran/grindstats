# Test cases: Administering user accounts

| ID | Title | Type | Linked scenario | Preconditions | Steps | Test data | Expected result | Priority |
|----|-------|------|-----------------|---------------|-------|-----------|-----------------|----------|
| TC-01 | Suspending a user ends sessions and blocks login | Happy path | suspending a user immediately ends their sessions and blocks login | User has 2 active sessions | 1. Admin: `POST /admin/users/{id}/suspend`<br>2. Attempt requests from both sessions<br>3. Attempt login as that user | Target user with 2 sessions | Both sessions invalidated; login fails `AUTH_ACCOUNT_SUSPENDED`; audit record written | P1 |
| TC-02 | Unsuspending allows login but not old sessions | Edge | unsuspending restores the ability to log in, but not old sessions | Account currently suspended | 1. Admin: `POST /admin/users/{id}/unsuspend`<br>2. User logs in<br>3. Attempt to reuse a pre-suspension token | Previously suspended account | New login succeeds; pre-suspension tokens remain invalid | P2 |
| TC-03 | Force-logout ends sessions without suspending | Happy path | force-logout ends sessions without suspending | User has active sessions, account in good standing | 1. Admin: `POST /admin/users/{id}/force-logout`<br>2. Attempt existing session's requests<br>3. User logs in again | Target user | Sessions invalidated; account not suspended; immediate re-login succeeds; audit record written | P1 |
| TC-04 | Admin views sessions/security events without seeing credentials | Happy path | admin can view sessions and security events but never credentials | Target has login failures on record | 1. Admin: `GET /admin/users/{id}/sessions`<br>2. Admin: `GET /admin/users/{id}/security-events` | Target user with history | Device labels, timestamps, event types returned; no password/hash/token value present anywhere in the response | P1 |
| TC-05 | Granting SystemAdmin invalidates the target's existing token | Happy path | granting SystemAdmin invalidates the target's existing tokens | Target logged in as User | 1. Admin: `PUT /admin/users/{id}/role` → SystemAdmin<br>2. Attempt an action with the target's pre-grant access token | Valid pre-grant token | Pre-grant token rejected (epoch check); target must obtain a new token to use elevated access | P1 |
| TC-06 | Revoking SystemAdmin removes elevated access immediately | Happy path | revoking SystemAdmin immediately removes elevated access | Target currently SystemAdmin, logged in | 1. Admin: `PUT /admin/users/{id}/role` → User<br>2. Attempt an admin action with the target's pre-revoke token | Valid pre-revoke SystemAdmin token | Rejected on epoch check before role check; target's admin capability gone | P1 |
| TC-07 | Role management is absent from the SPA | Regression | role grant/revoke is not reachable through the SPA UI | Logged in as SystemAdmin in the web app | 1. Inspect the SPA's UI and routes for any role-management control | — | No UI path exists; the action is API/ops-only | P2 |
| TC-08 | Every admin action is audit-logged and cannot be deleted | Regression | every admin action writes an undeletable audit record | Any admin action just performed | 1. Perform suspend, force-logout, and role-change actions<br>2. Attempt to find or call any endpoint that deletes an audit record | — | Each action has a corresponding audit record with actor/action/target/timestamp/request ID; no delete path exists | P1 |
| TC-09 | User token on an admin route gets 403, not 404 | Negative | a User token is forbidden, not not-found, on admin routes | Authenticated as User | 1. Call any `/admin/*` endpoint with a User-role token | User-role token | 403 `AUTH_FORBIDDEN` | P1 |
| TC-10 | No admin route can reach a user's health data | Negative | admin scope cannot reach a user's health data through any admin endpoint | SystemAdmin authenticated | 1. Enumerate `/admin/*` routes<br>2. Attempt to construct a request for a target's metrics/meals/routines/chat under `/admin/` | SystemAdmin token | No such route exists; request fails at routing, not merely at a permission check | P1 |
| TC-11 | Unauthenticated request to an admin route is rejected before role is even considered | Negative | (cross-cutting with FR-20, auth-session-refresh-logout) | No token presented | 1. Call an `/admin/*` endpoint with no auth token | — | 401 `AUTH_INVALID_TOKEN`, not 403 — authentication is checked before authorization | P2 |
